  1. Step 1

    Hold the one idea.

    A system can say “I feel,” “I remember,” or “I prefer.” That language is easy to read as proof of an inner subject.

    The research idea is stricter: the report does not, by itself, tell you whether there is a subject, which process is the subject, or whether the reporting system is the same thing as the thing being reported.

    We call this the Subject–Report Identification Problem. Everything else is how to study it without overclaiming.

  2. Step 2

    Separate four questions by hand.

    Tap a layer. Only one is the target property.

    Origin

    How the system was produced matters historically. It does not, by itself, settle whether anything is present now.

  4. Step 4

    Built is not proven.

    Built and public

    • Living book and theory materials
    • Experiment and analysis designs
    • Claims and originality ledgers
    • Public evidence and readiness controls
    • Repository tests for engineering contracts

    Not established

    • A validated consciousness test
    • A confirmatory human EGC result
    • A completed synthetic cloud dry run
    • Proof of awareness, deception, or hidden intent from one output contrast

  5. Step 5

    Experience the argument itself.

    1. Run the four-stage case — watch which proxy decides for you.
    2. Probe the signal instrument — change a report without settling presence.
    3. Build an evidence constellation — qualitative pressure, no score.
    4. Fork continuity — same transcript, two branches.
    5. Check the claims ledger — supported vs speculative.
